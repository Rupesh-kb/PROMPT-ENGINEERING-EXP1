(a) GANs - Generative Adversarial Networks

        Random noise -> [GENERATOR] -> Fake image --+
                                                    +--> [DISCRIMINATOR] -> Real or Fake?
        Real images  -------------------------------+            |
              ^                                                  |
              +------------ feedback to both networks -----------+
 
(b) VAEs - Variational Autoencoders
    Encoder squeezes data into a small "latent code"; decoder rebuilds it.

### DIFFERENT ARCHITECTURES OF GENERATIVE AI – FOCUS ON TRANSFORMERS
============================================================

2.1 INTRODUCTION

An AI architecture is the basic structure or design of an AI model. It
describes how the model processes input data, learns information, and
generates output.

Important Generative AI architectures include: 1. Generative Adversarial
Networks (GANs) 2. Variational Autoencoders (VAEs) 3. Autoregressive
Models 4. Diffusion Models 5. Recurrent Neural Networks (RNNs) and LSTMs
6. Transformers

2.2 GENERATIVE ADVERSARIAL NETWORKS (GANs)

A GAN contains two neural networks: - Generator: Creates artificial data
such as images. - Discriminator: Checks whether the generated data is
real or fake.

The two networks compete. The Generator tries to create realistic
content, while the Discriminator tries to identify fake content.

Diagram:

       Random Noise
             |
             v
         GENERATOR
             |
             v
       Generated Image
             |
             v
       DISCRIMINATOR
             |
       Real or Fake?

Applications: - Face generation - Image creation - Medical-image
generation - Video generation

2.3 VARIATIONAL AUTOENCODERS (VAEs)

A VAE learns important features of input data and uses them to generate
new data.

It contains: - Encoder: Converts input data into a compressed
representation called latent space. - Decoder: Uses the latent
representation to reconstruct or generate data.

Diagram:

       Input Image
            |
            v
          ENCODER
            |
            v
        Latent Space
            |
            v
          DECODER
            |
            v
       Generated Image

Applications: Image generation, image reconstruction, data compression,
and anomaly detection.

2.4 AUTOREGRESSIVE MODELS

Autoregressive models generate content one step at a time by predicting
the next element based on previously generated elements.

Example:

Artificial | v Artificial Intelligence | v Artificial Intelligence is |
v Artificial Intelligence is useful.

Applications: Text generation, chatbots, language translation, and code
generation.

2.5 DIFFUSION MODELS

Diffusion models are commonly used for image generation. They learn to
remove noise from data.

Forward process: Original Image -> Add a little noise -> Add more noise
-> Random noise

Reverse process: Random noise -> Remove noise step by step -> Clear
generated image

Applications: Image generation, digital art, image editing, and video
generation.

2.6 RNNs AND LSTMs

Recurrent Neural Networks (RNNs) process sequential data one element at
a time and maintain information from previous steps.

LSTM (Long Short-Term Memory) is an improved type of RNN that can retain
important information for longer periods.

Applications: Speech recognition, language processing, time-series
prediction, and text generation.

2.7 TRANSFORMER ARCHITECTURE

A Transformer is a deep-learning architecture introduced in 2017 in the
research paper “Attention Is All You Need.”

It uses an important technique called the attention mechanism.
Transformers can process multiple input tokens in parallel during
training, unlike traditional RNNs that process sequences step by step.

Examples of Transformer-based models: - GPT models - BERT - T5 - Gemini
and other modern multimodal models use Transformer-based techniques.

Main features: 1. Uses attention to identify important information. 2.
Processes multiple tokens in parallel during training. 3. Learns
relationships between words. 4. Handles long-range relationships
effectively. 5. Can be adapted to text, images, audio, and other data.

2.8 BASIC TRANSFORMER ARCHITECTURE

The original Transformer has two major parts: 1. Encoder – Processes and
represents input information. 2. Decoder – Generates output using
previous output tokens and encoder information.

The original Transformer contains encoder and decoder stacks. Modern
models may use only one part: GPT is decoder-only, while BERT is

2.9 HOW A TRANSFORMER WORKS

Example input: “The cat is sitting on the mat.”

Step 1 – Input Text: The user provides a sentence or instruction.

Step 2 – Tokenization: The sentence is divided into smaller units called
tokens. A token may be a word, part of a word, or punctuation mark.

Example: “The cat is sitting” -> [“The”, “cat”, “is”, “sitting”]

Each token is assigned a numerical ID.

Step 3 – Word Embedding: Each token is converted into a numerical vector
called an embedding. These vectors help the model learn relationships
and meanings.

Step 4 – Positional Information: The model needs information about token
order. Positional information is added to token embeddings so the model
can distinguish word positions.

Step 5 – Self-Attention: The model identifies how words in the sentence
relate to one another.

Example: “The animal was tired because it had been running.” The model
can learn that “it” refers to “animal”.

Step 6 – Feed Forward Network: The information from attention is
processed further to learn complex patterns.

Step 7 – Output Generation: A decoder-based model predicts the next
token. The process continues until the response is complete.

2.10 ENCODER ARCHITECTURE

The encoder processes the input sentence and identifies relationships
between words.

Main components: 1. Multi-Head Self-Attention 2. Add and Normalize 3.
Feed Forward Neural Network 4. Add and Normalize

Functions: - Self-Attention: Identifies relationships between words. -
Add and Normalize: Combines original and processed information and
supports stable learning. - Feed Forward Network: Processes information
further. - Encoder Output: Provides contextual representations.

2.11 DECODER ARCHITECTURE

The decoder generates new content based on previously generated tokens
and, in the original encoder-decoder Transformer, the encoder output.

Main components: 1. Masked Multi-Head Self-Attention 2. Add and
Normalize 3. Cross-Attention 4. Add and Normalize 5. Feed Forward
Network 6. Add and Normalize

                 |

Masked self-attention prevents the decoder from looking at future
tokens. Cross-attention connects the decoder with encoder output.

Machine-translation example:

2.4 STEP-BY-STEP: HOW A TRANSFORMER WORKS
------------------------------------------------------------------------------
 
STEP 1: TOKENIZATION
  Break text into small units called tokens and give each an ID number.
     "Cats are cute"  ->  [ "Cats", " are", " cute" ]  ->  [5421, 389, 9821]
 
STEP 2: EMBEDDING
  Each token ID becomes a vector (a long list of numbers) that captures meaning.
  Similar words get similar vectors.
     "king"  -> [0.8, 0.1, 0.9, ...]
     "queen" -> [0.8, 0.2, 0.9, ...]   (close to king)
     "apple" -> [0.1, 0.9, 0.2, ...]   (far from king)
 
STEP 3: POSITIONAL ENCODING
  Transformers see all words at once, so they do not know word ORDER.
  We add a position signal to each vector:
     "Dog bites man"  is different from  "Man bites dog".
 
STEP 4: SELF-ATTENTION (the heart of the Transformer)  -- see 2.5
 
STEP 5: MULTI-HEAD ATTENTION
  Run several attention "heads" in parallel; each learns a different
  relationship (grammar, meaning, who-did-what). Results are combined.
 
STEP 6: ADD & NORMALIZE (residual connection + layer norm)
  Add the original input back to the output and normalize the numbers.
  This keeps training stable and prevents information from being lost.
 
STEP 7: FEED-FORWARD NETWORK
  A small neural network applied to each token separately to process and
  transform what attention gathered.
 
STEP 8: REPEAT
  Steps 4-7 form ONE Transformer block. Stack many (e.g., 12, 48, 96+).
  Early layers learn simple patterns (grammar); later layers learn deeper
  meaning (reasoning, facts).
 
STEP 9: OUTPUT LAYER (Linear + Softmax)
  Converts the final vector into a probability for every word in the
  vocabulary.
     "The cat sat on the ___"   mat 62%  | floor 15% | sofa 8% | ...
 
STEP 10: PICK THE NEXT TOKEN AND REPEAT
  Choose a token (highest probability, or sampled with some randomness),
  append it to the input, and run again until the answer is complete.
 
 
2.5 ATTENTION AND SELF-ATTENTION
------------------------------------------------------------------------------
ATTENTION: lets the model focus on the most relevant parts of the input when
producing each output. Like highlighting the important words while reading.
 
SELF-ATTENTION: every word in a sentence looks at every other word in the
SAME sentence to understand context.
 
Example: "The animal didn't cross the street because IT was too tired."
  What does "it" refer to? Self-attention gives "it" a strong link to "animal".
 
   The  animal  didn't  cross  the  street  because  [it]  was  tired
                 ^^^^^^^                               |
                 strong attention  <-------------------+
 
QUERY, KEY, VALUE (Q, K, V) - the simple library analogy:
  Query (Q) : what I am looking for        ("I need info about 'it'")
  Key   (K) : what each word offers/labels  (each word's index card)
  Value (V) : the actual content of the word
 
Each word's vector is multiplied by three learned weight matrices to make Q, K, V.
 
ALGORITHM (step by step):
 
   Input vectors X
        |
        +--> x Wq --> Q (queries)
        +--> x Wk --> K (keys)
        +--> x Wv --> V (values)
                |
   1. Score      = Q . K(transpose)         (how related is each pair?)
   2. Scale      = Score / sqrt(dk)         (keeps numbers stable)
   3. (Mask)     = hide future words        (decoder only)
   4. Softmax    = turn scores into percentages that sum to 100%
   5. Weighted sum = Softmax weights x V    (blend values by importance)
        |
        v
   Output: each word's NEW vector, now enriched with context
 
   Formula:   Attention(Q,K,V) = softmax( Q K^T / sqrt(dk) ) V
 
Tiny attention table for the word "it" (illustrative numbers):
 
     Word attended    | animal | street | tired | the
     Attention weight |  60%   |  15%   |  20%  |  5%
 
MASKED SELF-ATTENTION (decoder): a word may only look at EARLIER words, not
future ones. Otherwise the model could "cheat" while learning to predict.
 
CROSS-ATTENTION (encoder-decoder): decoder's Queries look at the encoder's
Keys and Values, so the output stays tied to the input.
 
MULTI-HEAD ATTENTION:
 
   X --> [Head 1] --+
   X --> [Head 2] --+--> Concatenate --> Linear --> Output
   X --> [Head 3] --+
   X --> [Head n] --+
   (each head focuses on a different type of relationship)
 
WHY TRANSFORMERS ARE POWERFUL:
  + Parallel processing (fast training on GPUs)
  + Captures long-range context
  + Scales very well with more data and compute
  + Works for text, images, audio, video, proteins

Data collection is the first stage in building an LLM. Large amounts of

Example: To build a model that understands English and Tamil, suitable

5.5 STEP 2 – DATA PREPROCESSING

Data preprocessing cleans and prepares collected data before it is given
to the AI model.

Raw data may contain spelling errors, duplicate sentences, unnecessary

Activities: 1. Remove duplicate content. 2. Remove unwanted or

5.6 STEP 3 – TOKENIZATION

Tokenization divides text into smaller units called tokens.

A token can be: - A complete word. - Part of a word. - A punctuation
mark. - A special symbol.

Text is converted into tokens and then into numerical IDs so the model
can process it.

Example:

Input: “Generative AI is useful.”

Tokens: [“Generative”, “AI”, “is”, “useful”, “.”]

Each token is assigned a numerical ID by the tokenizer. The actual
tokenization depends on the tokenizer used by the model.

processing easier. 3. Helps the model learn language patterns. 4.
Provides numerical input to the neural network.

5.7 STEP 4 – MODEL ARCHITECTURE

Model architecture defines how the model processes information and
generates responses.

Most modern LLMs use the Transformer architecture.

A Transformer uses an attention mechanism to understand relationships
between tokens.

Example: “The student studied hard because she had an exam.” The model
can learn that “she” refers to “student”.

Main Transformer components: 1. Input Embedding 2. Positional
Information 3. Self-Attention 4. Feed Forward Neural Network 5. Output
Layer

Transformer model types:

A. Encoder-only: - Mainly understands and analyzes input text. -
Example: BERT. - Applications: Text classification and sentiment
analysis.

B. Decoder-only: - Generates text one token at a time. - Example: GPT
models. - Applications: Chatbots, text generation, and code generation.

C. Encoder-Decoder: - Encoder understands input; decoder generates
output. - Example: T5. - Applications: Translation and summarization.

5.8 STEP 5 – MODEL TRAINING

Model training teaches the AI model patterns from prepared training
data.

During training, the model reads text and learns to predict the next
token. This is commonly called next-token prediction.

Example sentence: “Artificial Intelligence is changing the world.”

  Input                                     Expected next token
  ----------------------------------------- ---------------------
  Artificial                                Intelligence
  Artificial Intelligence                   is
  Artificial Intelligence is                changing
  Artificial Intelligence is changing       the
  Artificial Intelligence is changing the   world

The model compares its prediction with the expected token and calculates
an error. It then adjusts its internal parameters to reduce that error.
This process is repeated many times.

Training flowchart:

Important training terms:

1.  Parameters: Numerical values learned by the model.
2.  Loss Function: Measures how far predictions are from expected
    answers.
3.  Backpropagation: Calculates how parameters contributed to prediction
    error.
4.  Gradient Descent: An optimization method used to update parameters
    and reduce error.
5.  Epoch: One complete pass through the training dataset.

Example: If the expected next token is “apple” but the model predicts
“orange”, training calculates the error and adjusts parameters to
improve future predictions.

5.9 STEP 6 – FINE-TUNING

Fine-tuning takes an already pretrained model and trains it further
using a smaller, more specific dataset.

Purpose: Improve the model for particular tasks or instructions.

Example: A general LLM can answer questions about many subjects.
Fine-tuning it with engineering question-and-answer examples can make it
more suitable for engineering assistance.

Fine-tuning process:

Types of fine-tuning:

A. Supervised Fine-Tuning (SFT): The model is trained using examples
containing questions and desired answers. Example: Question: What is
IoT? Answer: IoT is a network of connected devices that exchange data.

B. Instruction Fine-Tuning: The model is trained to follow user
instructions. Example: Instruction: Explain cloud computing in five
points. Expected response: A simple five-point explanation.

C. Preference-Based Training: The model is optimized using human or AI
feedback about which responses are more helpful and appropriate. One
approach is Reinforcement Learning from Human Feedback (RLHF).

Importance: - Improves task-specific performance. - Helps the model
follow instructions. - Improves response quality. - Makes the model
suitable for specialized applications.

5.10 STEP 7 – TEXT GENERATION

Text generation is the stage where the trained LLM produces an answer
based on the user’s prompt.

The model predicts one token at a time and combines the generated tokens
into sentences.

Working process: 1. User enters a prompt. 2. Prompt is converted into
tokens. 3. Model processes the tokens. 4. It predicts the next token. 5.
A token is selected using the model’s prediction and generation
settings. 6. The process repeats until the response is complete.

Example:

User Prompt: “Explain IoT in simple words.”

Generated Response: “IoT stands for Internet of Things. It connects
physical devices to the internet so they can collect and exchange data.”

LARGE LANGUAGE MODELS (LLMs) - HOW THEY ARE BUILT
##############################################################################
 
5.1 WHAT IS AN LLM?
------------------------------------------------------------------------------
A Large Language Model is a very large neural network (usually a Transformer)
trained on huge amounts of text to understand and generate human language.
Its core skill: PREDICT THE NEXT TOKEN.
 
Think of an advanced "autocomplete" that has read a large part of the
internet, books, and code.
 
   "The capital of France is ___"  -> "Paris"  (highest probability)
 
Examples: GPT series, Claude, Gemini, LLaMA, Mistral.

STEP 1: DATA COLLECTION
------------------------------------------------------------------------------
Gather very large and varied text.
  Sources: websites (e.g., Common Crawl), books, Wikipedia, research papers,
           news, code repositories (GitHub), forums, licensed datasets.
  Scale  : trillions of tokens for modern models.
  Why variety matters: so the model learns many topics, styles, and languages.
  Real-world example: a model that must write code needs lots of code data.
 
STEP 2: DATA PREPROCESSING (CLEANING)
------------------------------------------------------------------------------
Raw data is messy, so we:
  - Remove duplicates (stops memorising repeated text)
  - Filter low-quality text, spam, broken HTML
  - Remove harmful content and personal information (privacy)
  - Detect language, fix formatting
  - Balance the mix of sources (code, books, web)
  - Split into training / validation / test sets
 
   Raw web text -> [dedupe] -> [quality filter] -> [safety/PII filter]
                -> Clean training corpus
 
STEP 3: TOKENIZATION
------------------------------------------------------------------------------
Computers need numbers, so text is split into TOKENS (pieces of words) and each
is given an ID. Common method: Byte Pair Encoding (BPE) or similar subword
methods.
 
   "Unbelievable!"  ->  ["Un", "believ", "able", "!"]  ->  [3118, 9427, 540, 0]
 
Why subwords? A fixed vocabulary (e.g., 50,000 to 200,000 tokens) can handle
any new or rare word by combining pieces.
Roughly: 1 token = about 3/4 of an English word.
 
   Text -> Tokens -> Token IDs -> Embedding vectors -> Model
 
STEP 4: MODEL ARCHITECTURE
------------------------------------------------------------------------------
Most LLMs use a DECODER-ONLY TRANSFORMER:
 
   Token IDs
      |
   Embedding + Positional information
      |
   [ Transformer block ]  x N layers
        - Masked multi-head self-attention
        - Feed-forward network
        - Residual connections + normalization
      |
   Output layer (Linear + Softmax) -> probability for every token
 
Key design choices: number of layers, hidden size, number of attention heads,
context window length (how much text it can read at once), vocabulary size.
These choices decide the number of parameters (millions to hundreds of
billions).
 
STEP 5: PRE-TRAINING
------------------------------------------------------------------------------
Goal: learn language by predicting the next token over the whole dataset.
This is SELF-SUPERVISED learning: the text itself provides the answers, so no
human labelling is needed.
 
   Input : "The sun rises in the"
   Target: "east"
 
   Training loop:
   +--> Feed a batch of text
   |        |
   |        v
   |   Model predicts next tokens
   |        |
   |        v
   |   Compute LOSS (cross-entropy: how wrong was it?)
   |        |
   |        v
   |   BACKPROPAGATION: find how each weight contributed to the error
   |        |
   |        v
   |   OPTIMIZER (e.g., Adam) nudges weights to reduce error
   +--------+   (repeat billions of times)
 
Needs thousands of GPUs/TPUs running for weeks or months.
Result: a BASE MODEL (knows language and facts, but may not follow
instructions well; it just continues text).
 
STEP 6: FINE-TUNING AND ALIGNMENT
------------------------------------------------------------------------------
Make the base model useful, safe, and helpful.
 
  (a) Supervised Fine-Tuning (SFT)
      Train on examples of good instruction -> response pairs written by humans.
         Instruction: "Summarise this paragraph."  Response: (good summary)
 
  (b) Learning from Human Feedback (RLHF) and similar methods
      Humans rank several answers; the model is trained to prefer the
      better-ranked ones.
 
        Prompt -> Model gives answers A, B, C -> Humans rank them
              -> Reward model learns preferences
              -> Model is updated to produce higher-reward answers
 
  (c) Other options: domain fine-tuning (medical, legal), safety training,
      parameter-efficient methods such as LoRA (train only a small add-on).
 
  Real-world example: base model -> instruction tuning -> a helpful chat
  assistant that refuses harmful requests.
 
STEP 7: EVALUATION AND SAFETY TESTING
------------------------------------------------------------------------------
  - Benchmarks (knowledge, reasoning, maths, coding tests)
  - Human evaluation of answer quality
  - Red-teaming (experts try to make it fail or misbehave)
  - Checks for bias, toxicity, privacy leaks, hallucination
 
STEP 8: DEPLOYMENT
------------------------------------------------------------------------------
Offer the model through an app, website, or API. Optimise speed and cost
(quantization, caching, batching). Add safety filters and monitoring.
 
STEP 9: TEXT GENERATION (INFERENCE)
------------------------------------------------------------------------------
How the trained model answers you:
 
   User prompt: "Write a poem about rain"
        |
        v
   Tokenize -> run through Transformer -> probabilities for next token
        |
        v
   SELECT a token using a decoding strategy
        |
        v
   Append token to the text -> feed back in -> repeat until finished
        |
        v
   Detokenize (tokens -> readable text) -> show to user
 
   Decoding strategies:
     Greedy search   : always pick the most likely token (safe, repetitive)
     Sampling        : pick randomly according to probabilities (more creative)
     Temperature     : low = focused and predictable; high = creative and varied
     Top-k / Top-p   : only choose among the most likely candidates
     Beam search     : keep several best candidate sentences
 
   Example: next-token probabilities after "The weather today is"
      sunny 40% | cloudy 25% | rainy 20% | cold 10% | other 5%
   Low temperature -> almost always "sunny"; high temperature -> more variety.
